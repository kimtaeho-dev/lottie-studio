# lottie-studio

디자이너를 위한 **프로덕션용 Lottie 애니메이션** 제작 도구입니다. 코딩
에이전트가 Lottie 파일을 직접 쓰고, 로컬 플레이어가 바로 화면에 그려줍니다.

미리보기 화면과 실제 서비스에 쓰이는 화면은 완전히 같지 않아서, 미리보기에서는
멀쩡해 보여도 실제 서비스에서는 다르게 보일 수 있습니다. 이 차이를 확인하고
메꾸는 작업은 전부 에이전트가 알아서 처리하니, 아래 가이드를 따라가는 동안
코드나 JSON을 직접 들여다볼 일은 없습니다.

## 30초 요약

피그마처럼 화면을 보면서 작업하지만, 실제로 애니메이션 파일을 쓰는 건 AI
에이전트입니다. 할 일은 딱 세 가지입니다.

1. **말합니다** — 원하는 애니메이션을 에이전트에게 설명합니다.
2. **봅니다** — 플레이어 화면에서 재생해보고, 마음에 안 들면 다시 말합니다.
3. **내보냅니다** — 완성되면 Export 버튼으로 파일을 받습니다.

터미널이나 코드는 물론, git도 몰라도 괜찮습니다. 앱을 받아서 열면 나머지는
앱이 알아서 준비합니다. 이 문서는 앱을 받는 순간부터 완성본을 내보내는 순간까지
순서대로 따라가면 되도록 A→H로 구성했습니다.

## A. 앱 받아서 열기

**Lottie Studio는 앱입니다.** 터미널도, git도, Node.js 같은 사전 설치도 필요
없습니다.

1. [Releases 페이지](https://github.com/kimtaeho-dev/lottie-studio/releases/latest)에서
   `Lottie.Studio-<버전>-arm64.dmg`를 받습니다. (2020년 이전 인텔 맥이라면
   `arm64`가 안 붙은 쪽을 받으세요.)
2. 받은 파일을 두 번 눌러 열고, **Lottie Studio**를 응용 프로그램 폴더로
   끌어다 놓습니다.
3. 응용 프로그램에서 **Lottie Studio**를 두 번 누릅니다.

> **처음 열 때 "확인할 수 없는 개발자" 경고가 나올 수 있습니다.** 이 앱이 Apple에
> 유료 등록된 배포자 서명을 달고 있지 않아서 뜨는 안내이고, 딱 한 번만 나옵니다.
> **시스템 설정 → 개인정보 보호 및 보안**으로 가서 아래쪽 **"확인 없이 열기"**를
> 누르면 됩니다. 그 다음부터는 그냥 열립니다.

만든 애니메이션은 앱이 아니라 내 폴더(`~/라이브러리/Application Support/Lottie
Studio/`)에 저장되므로, 나중에 새 버전 앱으로 덮어써도 작업물은 사라지지
않습니다.

<details>
<summary>개발자라면: 레포에서 직접 실행하기</summary>

`git clone` 후 `npm install && npm run dev`로 기존처럼 개발 서버를 띄울 수
있습니다. 앱을 직접 만들려면 `npm run dist:mac`을 실행하면 `release/`에 dmg가
생깁니다.

</details>

## B. 처음 열 때 한 번만 — 에이전트 준비

앱을 처음 열면 준비 화면이 나옵니다. 애니메이션을 실제로 만들어 주는 **에이전트
(Claude Code)** 를 이 컴퓨터에 두는 과정이고, 버튼을 누르면 앱이 알아서
처리합니다.

1. **설치** — "설치 시작"을 누르면 앱이 알아서 내려받아 설치합니다. 몇 분 걸릴
   수 있습니다.
2. **로그인** — "로그인 시작"을 누르면 브라우저가 열립니다. Anthropic 계정으로
   로그인하면 코드가 나오는데, 그걸 복사해서 앱 화면의 입력칸에 붙여넣으면
   끝입니다.

이 두 단계는 **처음 한 번만** 합니다. 다음부터는 앱을 열면 바로 작업 화면이
나옵니다. 이미 Claude Code를 쓰고 있었다면 이 화면 자체가 안 나옵니다.

## C. 플레이어 화면 익히기

준비가 끝나면 아래 화면이 나타납니다.

| 위치 | 이름 | 하는 일 |
| --- | --- | --- |
| 왼쪽 | 프로젝트 사이드바 | 애니메이션 목록입니다. `+`로 새 프로젝트를 만듭니다 |
| 가운데 | 캔버스 | 실제 애니메이션이 그려지는 곳입니다 |
| 캔버스 하단 | 재생바 | 재생/정지 버튼, 스크러버(슬라이더), 현재 프레임 / 전체 프레임, fps |
| 오른쪽 위 | 줌 · Export | 화면 확대/축소, 완성본 내보내기 |
| 오른쪽 | 속성 패널 | 에이전트가 편집 가능하게 열어둔 값(색상, 숫자, 텍스트)을 직접 만지는 곳입니다 |
| 오른쪽 아래 | 에이전트 | 여기에 바로 타이핑해서 요청합니다. 애니메이션을 만들고 고치는 일은 전부 이 창에서 이뤄집니다. SVG 파일을 끌어다 놓거나 클립 아이콘으로 첨부하면 그 SVG를 기반으로 애니메이션을 만들어달라고 요청할 수도 있습니다. 진행 중인 요청은 취소할 수 있고, 헤더의 초기화 버튼으로 대화를 새로 시작할 수도 있습니다 |

가지고 있는 `.json`/`.lottie` 파일을 캔버스에 그대로 끌어다 놓으면 새 씬으로
바로 열립니다 — 전에 만들어둔 애니메이션을 가져올 때 쓰면 됩니다.

## D. 에이전트에게 애니메이션 요청하기

화면 오른쪽 아래 **에이전트** 채팅창에 원하는 걸 그대로 타이핑하면 됩니다.
코드나 JSON 문법을 몰라도 됩니다 — 원하는 느낌, 색, 길이, 배경 여부만 말로
설명하면 됩니다.

> 예: "제품 출시 로워서드를 만들어줘. 1920×1080, 60fps, 3초. 배경은 투명,
> 브랜드 컬러는 #2F6BFF. ease-in-out 타이밍으로."

어떤 프롬프트가 어떤 결과로 이어지는지 감이 안 온다면
[`docs/EXAMPLES.md`](docs/EXAMPLES.md)를 먼저 봐주세요. 실제로 만든 씬 5개와,
그 씬을 만들 때 쓴 프롬프트 원문이 나란히 있습니다. 그대로 복사해서 써도 되고,
숫자·색·문구만 바꿔서 시작해도 됩니다.

### 프롬프트를 잘 쓰는 요령

- **근거를 줍니다.** 참고 이미지, 스크린샷, 실제 브랜드 컬러 코드가 있으면
  결과가 확연히 좋아집니다. 디자이너가 만든 SVG 파일이 있다면 채팅창에 직접
  끌어다 놓거나 첨부해서 "이 SVG를 기반으로 만들어줘"라고 요청할 수 있습니다.
- **모션 용어로 말합니다.** 아래 [용어집](#h-용어집)에 있는 이징, 스태거,
  오버슈트 같은 말이 통합니다. 몰라도 "통통 튀는 느낌", "차분하게 착 붙는
  느낌"처럼 일상어로 설명해도 충분합니다.
- **카메라처럼 생각합니다.** 화면이 가까워지는지(푸시인), 옆으로 훑는지(팬),
  확대되는지(줌) 같은 카메라 무빙을 말해줍니다.
- **필요한 컨트롤을 요구합니다.** 기본값은 배경색 정도만 속성 패널에
  노출됩니다. 나중에 직접 색이나 숫자를 바꾸고 싶은 값이 있으면 "이 값은
  속성 패널에서 만질 수 있게 해줘"라고 요청합니다.
- **fps와 길이를 못 박습니다.** "3초, 30fps"처럼 숫자로 말하면 결과가
  명확해집니다.

### 마음에 안 들면 그냥 다시 말하면 됩니다

한 번에 완벽한 결과가 나오지 않아도 괜찮습니다. "좀 더 통통 튀게", "색이 너무
쨍해", "3초는 짧으니까 5초로 늘려줘"처럼 눈에 보이는 것 그대로 말하면
에이전트가 다시 만들어줍니다. 완성될 때까지 몇 번이고 반복해도 됩니다.

에이전트가 씬을 고치면 화면이 실시간으로 갱신됩니다 — 새로고침할 필요도,
저장 버튼을 누를 필요도 없습니다. 만든 씬이 실제로 어디에 저장되는지는
[부록](#씬이-저장되는-곳)에 적어뒀습니다.

## E. 결과 확인하고 다듬기

재생바의 재생 버튼으로 전체를 보거나, 스크러버를 드래그해서 원하는 순간을
멈춰놓고 자세히 볼 수 있습니다. 특히 **시작 프레임 · 중간 프레임 · 마지막
프레임** 셋은 꼭 확인해보세요 — 애니메이션이 이상하게 잘리거나, 배경이 안
보이거나, 요소가 겹치는 문제는 대부분 이 세 순간에서 드러납니다.

에이전트가 속성 패널에 색상·숫자·텍스트 값을 열어뒀다면, 거기서 직접
조정할 수 있습니다.

- **색상**: 색상 칩을 클릭하면 색상 선택기가 나타납니다.
- **숫자**: 슬라이더를 드래그하거나 값을 직접 입력합니다.
- **텍스트**: 입력창에 바로 타이핑합니다.

여기서 바꾼 값은 **바로 파일에 저장됩니다** — "미리보기용 임시 값"이 아니라
실제 확정 값입니다. 다만 색이나 숫자 몇 개를 넘어서는 변경(타이밍, 구도, 새로운
요소 추가 등)은 속성 패널로는 안 되니 에이전트에게 말로 요청해주세요.

## F. 이상해 보일 때

씬을 다 만들거나 고친 뒤, 에이전트는 화면에 보이지 않는 곳에서 몇 가지 자동
검사를 거칩니다 — 미리보기 화면과 실제 서비스 화면이 다르게 보일 수 있는
부분을 찾아서 미리 고치는 과정입니다. 이 검사는 에이전트가 알아서 돌리고
결과를 요약해 알려주기 때문에, 직접 명령어를 칠 필요는 없습니다.

그래도 화면이 이상해 보인다면, 다음처럼 **구체적으로** 말해주시면 훨씬 빨리
고쳐집니다.

- "몇 초쯤(또는 몇 프레임쯤)에서 이상한지"
- "어떤 요소가 안 보이는지 / 잘못된 위치에 있는지"
- "색이 기대한 것과 어떻게 다른지"

### 자주 있는 문제

| 증상 | 원인 / 해결 |
| --- | --- |
| 앱이 "확인할 수 없는 개발자"라며 안 열린다 | 처음 한 번만 나옵니다. **시스템 설정 → 개인정보 보호 및 보안**에서 **"확인 없이 열기"**를 누르세요 ([A 단계](#a-앱-받아서-열기)) |
| 캔버스가 계속 빈 화면 | 배경이 **투명**으로 설정된 씬일 수 있습니다 — 로고·아이콘·오버레이류는 원래 배경이 없습니다. 체커보드 무늬가 보이면 정상입니다 |
| 채팅에 "설치되어 있지 않다"는 답이 온다 | 에이전트 설치가 중간에 끊긴 경우입니다. 앱을 껐다 켜면 준비 화면이 다시 나옵니다 |
| 채팅이 로그인하라고 한다 | 로그인이 만료됐습니다. 앱을 껐다 켜면 로그인 화면이 나옵니다 ([B 단계](#b-처음-열-때-한-번만--에이전트-준비)) |
| 속성 패널에 아무 값도 안 보인다 | 이 씬에 아직 조정 가능한 값이 없다는 뜻입니다 — 에이전트에게 원하는 값을 속성 패널에 열어달라고 요청하세요 |

## G. 완성본 내보내기

오른쪽 위 **Export** 버튼을 누르면 현재 프로젝트의 zip 파일이 다운로드됩니다.
안에는 이런 것이 들어있습니다.

```
<프로젝트 이름>.zip
  animations/   각 씬의 완성된 애니메이션(.json) 파일
  images/       씬에서 쓰인 이미지 에셋
  fonts/        씬에서 쓰인 폰트 파일 (있는 경우)
```

이 zip을 그대로 개발자/엔지니어에게 전달하면 됩니다. 특정 씬의 파일 하나만
필요하다면 그 씬의 `lottie.json` 하나만 줘도 충분합니다 — 저장 위치는
[부록](#씬이-저장되는-곳)에 있습니다.

## H. 용어집

| 용어 | 뜻 |
| --- | --- |
| **Lottie / JSON** | 애니메이션을 저장하는 파일 형식입니다. 벡터 데이터라서 화질 손상 없이 어떤 크기로도 재생됩니다 |
| **씬(scene)** | 애니메이션 한 편입니다. 프로젝트 하나에 씬이 여러 개 있을 수 있습니다 |
| **프레임 / fps** | 프레임은 정지 그림 한 장, fps는 1초에 그 그림을 몇 장 보여주는지입니다. 30fps·3초 = 90프레임 |
| **이징(easing)** | 움직임의 속도 변화입니다. "쭉 미끄러지듯"(ease-in-out), "탁 멈추듯"(ease-out) 같은 느낌을 결정합니다 |
| **스태거(stagger)** | 여러 요소가 동시에 안 움직이고 살짝씩 시간차를 두고 움직이는 것입니다 |
| **오버슈트(overshoot)** | 목표 지점을 살짝 지나쳤다가 되돌아오며 멈추는, 통통 튀는 듯한 움직임입니다 |
| **슬롯 / 컨트롤** | 속성 패널에서 직접 만질 수 있게 열어둔 값(색, 숫자, 텍스트)입니다 |
| **배경 정책** | 로고·아이콘·오버레이는 배경이 투명한 게 기본이고, 단독으로 완성된 화면(풀프레임)은 배경색이 있는 게 기본입니다 |
| **컴포지션** | 애니메이션의 캔버스 크기·길이·프레임 속도를 통틀어 부르는 말입니다 |
| **에이전트** | 실제로 애니메이션 파일을 쓰는 AI입니다. 채팅창에 말을 걸면 이 에이전트가 작업합니다 |
| **작업 폴더** | 만든 씬이 저장되는 내 컴퓨터의 폴더입니다. 앱을 새로 깔아도 여기 있는 작업물은 남습니다 |

## 부록: 명령어·씬 구조·체크리스트

아래는 직접 손을 대고 싶은 개발자나, 내부 동작이 궁금한 분을 위한 참고
자료입니다. 평소 작업 흐름에서는 몰라도 되고, 에이전트가 알아서 처리합니다.

### 명령어

| 명령 | 하는 일 |
| --- | --- |
| `npm install` | 의존성 설치 + `public/canvaskit.wasm` 생성 |
| `npm run dev` | 플레이어 dev 서버 (포트 3030) |
| `npm run app` | 빌드 후 앱을 바로 실행 (앱 개발용) |
| `npm run dist:mac` | 배포용 앱(dmg) 빌드 → `release/` |
| `npm run icon` | `public/mark.svg`로 앱 아이콘(`build/icon.icns`) 생성 |
| `npm run workspace:init` | 앱이 쓰는 작업 폴더를 만들거나 갱신 |
| `npm run check:lottie` | 모든 씬에 lottie-web 호환성 스캐너 실행 |
| `npm run check:motion` | 정지 프레임으로는 안 보이는 이징 스냅(재생 중 순간 튐) 검사, 브라우저 불필요 |
| `npm run check:text-slots` | 텍스트 슬롯 유니코드 테스트 |
| `npm run build` | 프론트엔드 프로덕션 빌드 |
| `npm run build:electron` | 앱 진입점 번들 (`dist-electron/`) |
| `npm run preview` | 빌드 결과물 미리보기 |

특정 씬 하나만 스캔하려면:

```bash
node scripts/check-lottie-web-compat.mjs public/projects/main-project/scene-1/lottie.json
```

### 씬이 저장되는 곳

앱으로 쓰면 만든 씬은 **앱 바깥, 내 사용자 폴더**에 저장됩니다.

```
~/라이브러리/Application Support/Lottie Studio/workspace/
  public/projects/<프로젝트>/<씬 번호>/lottie.json
```

앱 안이 아니라 여기에 두기 때문에, 나중에 새 버전 앱으로 덮어써도 작업물은
그대로 남습니다. Finder에서 찾으려면 메뉴의 **이동 → 폴더로 이동**에
`~/Library/Application Support/Lottie Studio/`를 붙여넣으면 됩니다.

레포를 직접 받아 `npm run dev`로 쓰는 경우에는 레포 안 `public/projects/`가
같은 역할을 합니다.

### 비교 페이지

```
<플레이어 주소>/compare.html?src=/projects/main-project/scene-1/lottie.json
```

주소는 개발 서버면 `http://localhost:3030`이고, 앱이면 실행할 때마다 포트가
달라질 수 있습니다 — 이 페이지는 에이전트가 확인용으로 쓰는 것이라 직접 열
일은 거의 없습니다.

왼쪽이 Skottie(미리보기), 오른쪽이 lottie-web SVG(프로덕션)입니다. 프레임
`0`, 중간, `op - 1`을 고정하고 **양쪽 패널을 둘 다** 봅니다. 두 패널이
다르면 그 원인을 없앨 때까지 고칩니다.

> **텍스트가 있는 씬은 판정이 반대입니다.** 두 패널의 글자가 서로 **다르게**
> 보이면 폰트가 양쪽에 제대로 들어간 것이라 정상입니다. **똑같이** 보이면
> 오히려 `@font-face` 주입이 실패해 양쪽 다 시스템 폰트로 폴백했을
> 가능성이 큽니다. 애초에 네이티브 텍스트(`ty:5`)는 BLOCK이므로 아웃라인으로
> 변환하는 게 정답입니다.

### 씬 구조

위 작업 폴더(앱) 또는 레포의 `public/projects/`(개발 서버) 아래 구조는
같습니다.

```
public/projects/
  <project>/
    <scene-N>/
      lottie.json      필수. 이게 없으면 씬으로 안 잡힌다
      controls.json    선택. 속성 패널 라벨/범위
      <이미지 파일>     assets[].p 에 파일명만 적어 참조
      <폰트 파일>       .ttf/.otf/.ttc (작업 중 네이티브 텍스트용)
```

`scene-<N>`의 뒤 숫자가 정렬 순서가 되고, 폴더 이름이 그대로 URL 세그먼트
(`/<project>/<scene>`)가 됩니다.

`public/projects/`는 로컬 작업 공간이라 git에 커밋되지 않습니다
(`.gitignore`). 앱이든 레포든 **빈 상태로 시작하고**, 여기에 들어가는 것은
전부 직접 만든 것입니다 — 어떤 경로로도 자동으로 채워 넣지 않습니다.

[`docs/EXAMPLES.md`](docs/EXAMPLES.md)에 소개된 씬의 완성 파일은 저장소의
`examples/` 폴더에 있습니다. 보고 싶으면 `lottie.json`을 캔버스에 끌어다
놓으면 새 씬으로 열립니다.

### 출고 전 체크리스트

1. JSON이 파싱되는가
2. `npm run check:lottie`가 BLOCK 0개로 통과하는가
3. `npm run check:motion`이 통과하는가 (정지 프레임엔 안 보이는 이징 스냅 검사 — 브라우저 불필요)
4. `/compare.html`에서 프레임 `0`, 중간, `op - 1`을 **양쪽 패널** 모두 봤는가 (브라우저를 쓸 수 있을 때)
5. 두 패널의 차이 원인을 제거했는가
6. 배경 정책이 용도에 맞는가
7. 씬 용량이 150KB 이하인가 (이미지는 base64 인라인 대신 외부 파일)
